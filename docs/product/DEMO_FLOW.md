# CutLab Studio Demo Flow

## Goal

Show the complete editor-to-client loop in 60-90 seconds: organize a job, deliver
a cut, collect precise feedback, finish the work, and see the business overview
update.

Target runtime: **75 seconds**

## Recording Setup

- Use a signed-in editor account with an otherwise quiet personal workspace.
- Record at 1440p or 1080p with the browser zoom at 100%.
- Prepare two small files before recording:
  - `launch-film-v1.mp4`
  - `launch-film-v2.mp4`
- Use the project name **Northstar Launch Film** and client **Northstar Coffee**.
- Set the deadline to a date within the next seven days.
- Keep the pointer movement deliberate and remove upload waiting time in the edit.
- Open the published portal in a separate incognito window so the no-account
  client experience is clear.

## 75-Second Sequence

| Time | Screen recording shot | On-screen action | Voiceover |
| --- | --- | --- | --- |
| 0-6s | Start on the dashboard. Briefly show the pipeline, deadlines, feedback, and earnings areas. | Slow push-in or subtle crop toward the dashboard metrics. | "Generic project tools bury editing work in noise. CutLab keeps the production details editors actually need in one place." |
| 6-15s | Open **Projects**, then select **New Personal Project** and **Blank project**. Keep the project form centered in frame. | Enter **Northstar Launch Film**, choose or type **Northstar Coffee**, set a due date, and save. | "Create the job, attach the client, and set the delivery date without building a task board first." |
| 15-25s | Open the new project and scroll to **Project Files**. | Select **Upload File**, upload `launch-film-v1.mp4` as a **Deliverable**, set the approval state to **Sent to Client**, and enable **Show in Client Portal**. | "The first cut lives inside the project as a client-visible deliverable, with its review state attached." |
| 25-33s | Keep the expanded deliverable card in view so its version history is readable. | Select **Upload Version**, add `launch-film-v2.mp4`, and show **Version 2** appearing above Version 1. | "Every new cut becomes an immutable version, so the handoff history never disappears." |
| 33-42s | Scroll to **Client Portal** and open the portal manager. | Select **Create Portal**, add a short client summary, choose **Publish Portal**, then use **Open**. | "Publish a private, client-safe portal without exposing internal notes, earnings, or team activity." |
| 42-53s | Cut to the incognito client portal. Frame the deliverable and revision form together if possible. | Enter the client name, add timecode **00:18**, type **Shorten the logo hold**, and select **Submit Request**. | "The client reviews without an account and leaves a revision tied to the exact moment that needs work." |

## Shot Direction

1. **Hook shot:** Use a clean dashboard with enough data to feel operational, but
   avoid a cluttered demo account.
2. **Form shots:** Crop closely enough that names, dates, and statuses remain
   readable after video compression.
3. **Version reveal:** Hold for one second after Version 2 appears so viewers can
   understand that both versions remain available.
4. **Portal transition:** Use a hard cut from the editor workspace to the
   incognito portal. The visual change should communicate the client boundary.
5. **Timecode moment:** Keep `00:18` and the submitted revision visible together.
   This is the strongest proof point in the demo.
6. **Completion shot:** Show both **Final Delivered** on the file and
   **Delivered** on the project. They represent separate, real states.
7. **Dashboard payoff:** End on changed numbers and recent activity rather than
   a static marketing screen.

## Honest Product Notes

- File uploads require the authenticated Convex-backed workspace. External links
  can be used instead when recording without a sample media file.
- The client portal is accessed through its private tokenized link and does not
  require a client account.
- **Final Delivered** is the deliverable approval state. **Delivered** is the
  project workflow status; the demo intentionally shows both.
- Dashboard totals and activity are derived from saved project data. Allow a
  brief moment for synchronized updates before recording the final shot.
